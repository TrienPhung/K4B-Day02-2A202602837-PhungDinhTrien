#### Problem Card #1 — Debug code khi làm bài tập lập trình

```text
Problem 1 câu:
Khi làm bài tập/đồ án lập trình, tôi thường mất nhiều thời gian debug vì gặp lại các lỗi tương tự (thiếu import, sai cú pháp, lỗi biên dịch) mà không có cách tra cứu nhanh.
Actor:
Sinh viên năm 4 ngành CNTT, tự làm bài tập lập trình cá nhân.

Thời điểm / bối cảnh:
Trong lúc làm bài lab/đồ án, thường xảy ra giữa buổi học hoặc khi tự làm bài ở nhà.

Current workflow 3-7 bước:
1. Chạy code, gặp lỗi
2. Đọc thông báo lỗi (error message)
3. Đoán nguyên nhân, thử sửa
4. Chạy lại để kiểm tra
5. Nếu vẫn lỗi, tìm kiếm trên Google/Stack Overflow
6. Áp dụng thử, chạy lại

Bottleneck:
Bước 5 (tìm kiếm) — mất nhiều thời gian vì phải đọc nhiều nguồn, lọc thông tin không liên quan.

Impact:
Mất khoảng 20-30 phút/lần, xảy ra khoảng 4-5 lần/tuần (~100-150 phút/tuần).

Success metric:
Giảm thời gian debug trung bình xuống dưới 10 phút/lần.

Non-AI alternative:
Ghi chép lại các lỗi thường gặp và cách sửa vào một file cá nhân (sổ tay lỗi) để tra cứu nhanh hơn.

AI hypothesis:
AI có thể đọc error message và gợi ý nguyên nhân/cách sửa nhanh hơn tìm kiếm thủ công.

Quick gut:
[ ] No AI / process fix
[ ] Rule
[x] Workflow
[ ] Agent
[ ] Chưa biết
```
